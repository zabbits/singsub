# Mihomo 文件脚本

在 Sub-Store「文件」中使用 `template.yaml`，添加 `scripts.js` 脚本操作。节点直接写入 `proxies`，模板的地区组也会填入具体节点名；不生成自动或故转组。

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `source` | 必填 | 主订阅或组合订阅名称，提供普通节点及中转候选 |
| `type` | `subscription` | 主来源类型：`subscription` 或 `collection` |
| `landings` | `[]` | 额外读取的落地订阅名称；这些来源始终按单个订阅读取 |
| `relay` | `HK,TW,JP,SG,US` | 生成地区中转组的国家代码及顺序；其他普通节点仍可在总中转组中选择 |
| `relayTag` | `🔗 中转选择` | 总中转组名称；与已有名称冲突时自动添加后缀 |

`landings` 和 `relay` 支持字符串数组、JSON 数组字符串、逗号或换行分隔字符串。未配置 `landings` 时，不新增任何中转组。

示例（替换为自己的订阅名称）：

```text
scripts.js#source=AIO&type=collection&landings=ExitA,ExitB&relay=HK,JP,SG
```

## 中转与落地

- 主来源中的普通节点提供中转；只有 `landings` 中的节点被标记为落地，不根据名称中的“落地”字样判断。
- 落地节点仍加入模板的地区组和“全部手动”，用于选择最终出口。
- 新增的地区中转组和总中转组只包含普通节点，不包含落地节点或模板的直连节点。
- 每个落地节点新增 `🔗 节点名 · 中转选择` 手动组，默认跟随总中转组，也可单独选择某个地区中转组。地区中转组本身是共享的。
- 使用 `dialer-proxy` 建立 `客户端 → 中转 → 落地 → 目标` 链路，不使用已废弃的 `type: relay`。
- 主来源和落地订阅出现同名节点时，只保留首次读取的配置，但按落地节点处理，并输出警告。若不是同一节点，请先在 Sub-Store 中重命名。
- 已有 `dialer-proxy` 链仅在落地节点集合内解析。脚本为每个落地节点复制链内辅助节点，并在链尾接入中转，避免共享链尾相互覆盖；生成的辅助节点不加入模板分组。
- 落地订阅读取失败、落地链循环或指向集合外部时，会警告并跳过。主来源失败、没有普通中转节点、名称冲突、静态节点与组存在悬空引用或代理循环时直接报错，不将落地静默改为直连。远程 provider 的节点内容不在此校验范围内。

中转节点需支持落地协议所需的 TCP/UDP。更新脚本后须重新生成配置并在 Mihomo 中更新；已有保存的手动选择可能继续生效。

## 测试

```sh
node --test scripts.test.js
# 可选：已安装 mihomo 时运行本地 SOCKS 多跳请求及中转切换测试
MIHOMO_TEST=1 node --test scripts.test.js
```

测试不使用真实订阅或外部服务器；可通过 `MIHOMO_BIN` 指定内核路径。
